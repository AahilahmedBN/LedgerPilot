# Kavach — `transactions.csv` Data Dictionary

Generated by `generate_synthetic_data.py`. Regenerate anytime with:
```
python3 generate_synthetic_data.py --rows 2800 --seed 42 --out transactions.csv
```
Same seed = same dataset, so results are reproducible across all three of you.

## Columns

| Column | Type | Description |
|---|---|---|
| `transaction_id` | string | Unique ID, `TXN000001` style |
| `date` | date (ISO) | Random date in 2024–2026 |
| `description_raw` | text | Noisy version — abbreviations, case variation, stray spaces. **Use this as classifier input** — it's the realistic case |
| `description_clean` | text | Clean version, no noise. Useful for debugging/inspection, not for training (too easy) |
| `amount` | float | INR, category-appropriate range (see `AMOUNT_RANGES` in the script) |
| `gst_rate` | enum | `0 / 5 / 12 / 18 / 28 / exempt` |
| `cgst_amount`, `sgst_amount`, `igst_amount` | float | Randomly intra-state (CGST+SGST split) or inter-state (IGST) — ~70/30 split, tune if you find better real-world data |
| `vendor_name` | text | Faker-generated Indian company name |
| `vendor_gstin` | string | **Format-plausible but fake** — only present on `invoice`/`receipt` rows, blank for `bank_statement_line` (real bank lines don't show GSTIN) |
| `document_type` | enum | `invoice / receipt / bank_statement_line` |
| `category` | text | Human-readable label (one of 14) |
| `category_key` | string | Machine key matching `categories.py` — **use this as your ML target, not `category`** |
| `itc_eligible` | enum | `Eligible / Blocked / Partially Eligible / Not Applicable` |
| `itc_blocked_reason` | text | Populated only when Blocked — cites the Sec 17(5) clause. This is what you quote in viva |
| `source` | string | Always `synthetic` here — keep this column even when you later add any real-derived rows, so the two are never silently mixed |

## The 14 categories (`category_key` values)

`purchase_goods, capital_goods, input_services, rent, utilities, bank_charges, motor_vehicle, food_catering, club_membership, employee_travel, employee_insurance, works_contract, sales_revenue, exempt_non_gst`

Full definitions, GST rates, and ITC reasoning for each are in `categories.py` — that file is the single source of truth. If you need to add/change a category, edit it there, not in the generator.

## Known simplifications (say these honestly in your report, don't hide them)

- Amount ranges are reasoned estimates, not empirically sourced from real MSME data — flag this if a judge/examiner asks.
- GST rate per category is a typical rate for demo purposes; real invoices vary by exact HSN/SAC code.
- This dataset has **no image noise** — it's for training/testing the categorization and ITC classifiers only. The OCR pipeline (Phase 2) needs separately sourced or rendered document images to test deskew/denoise/extraction robustness.
